### 알고리즘

**1단계 — 메모 키워드 (씨앗).** 메모에서 반복 등장하는 지명·고유명사를 뽑아 묶는다.

- **부분문자열 매칭을 써라.** 토큰/형태소 단위로 자르면 안 된다. 샘플에 `제주도`, `제주고`(사용자 오타), `김포>제주`가 섞여 있는데 부분문자열이어야 셋 다 잡힌다 (DESIGN.md 8.3)
- 2건 이상에서 등장하는 키워드만 이벤트로 인정한다

**2단계 — 시간 근접 (확장).** 씨앗으로 잡힌 거래의 **전후 5분 이내** 거래를 같은 이벤트에 흡수한다.

이게 필요한 이유가 실데이터에 있다 (DESIGN.md 2.5):
```
20:08:19  대한항공        -275,000  "제주>김포 항공권 2인"   ← 키워드로 잡힘
20:08:28  놀유니버스        -2,000  "항공권예약 대행수수료"   ← 9초 뒤. 키워드 없음
20:08:30  아시아나항공     -163,000  "김포>제주 항공권 2인"   ← 키워드로 잡힘
20:08:41  놀유니버스        -2,000  "항공권예약 대행수수료"   ← 11초 뒤. 키워드 없음
```
키워드만 쓰면 5건 778,430원이 나온다. 정답은 **7건 782,430원**이다. 차이 4,000원이 이 수수료 2건이다.

**부수 수수료가 메모에 지명을 갖지 않는 것은 일반 패턴이다** (예약 수수료, 환전 수수료). 시간 근접은 이걸 잡는 장치다.

### 테스트 (`src/lib/events.test.ts`)

픽스처 기반 (없으면 skip) — **소비 필터와 취소 제외를 적용한 뒤** 호출한다:
- `제주` 이벤트가 **7건 782,430원**. 5건 778,430원이 나오면 시간 근접 단계가 빠진 것이다
- `울진` 이벤트가 **0건**이다. 유일한 울진 지출 그린카가 취소 쌍이라 이미 제외됐다
- 놀유니버스 2건이 `제주` 이벤트에 포함된다

인라인 기반 (항상 실행):
- 오타 내성 — 메모 `제주도`/`제주고`가 같은 키로 묶인다
- 1건만 등장하는 키워드는 이벤트가 되지 않는다
- 시간 근접 확장이 5분을 넘으면 흡수하지 않는다

## 금지사항

- 이벤트를 `Category`로 만들지 마라. 별개 축이다. 이유: 카테고리로 넣으면 항공권→교통, 숙박→숙박으로 흩어지는 문제가 되돌아온다 (ADR-006)
- 토큰/형태소 단위 매칭을 쓰지 마라. 이유: `제주고` 오타가 빠져 50,630원이 누락된다 (DESIGN.md 8.3)
- 이벤트 기간을 거래일 범위로 계산해 "일평균"을 만들지 마라. 이유: 샘플의 7건이 **전부 같은 날(08.12) 예약**이다. 거래일은 예약일이지 여행 기간이 아니다 (DESIGN.md 4.9)
- 취소된 거래를 이벤트에 넣지 마라. 이유: 호출 전에 이미 제외돼야 한다 (step 3)
