### 알고리즘 (DESIGN.md 4.6)

1. 후보 키 = `적요(description)` + `절대금액`
2. **1:1 그리디 매칭** — 취소 행(양수, 거래 유형이 `체크카드결제`)마다, 같은 키를 가진 **가장 가까운 이전 미매칭 결제 1건**과만 짝짓는다. 짝지은 결제는 소진 처리한다
3. **시간 순서 제약** — `취소 시각 > 결제 시각`
4. **경과 시간에 상한을 두지 마라.** 샘플의 두 사례가 24초와 **42시간**이다

### 테스트 (`src/lib/cancel.test.ts`)

픽스처 기반 (없으면 skip):
- 취소 쌍이 정확히 **2건**
- `롯데시네마_티켓_토스페이_TOSS 36,000` (24초 간격)
- `(주)그린카 267,750` (42시간 간격)

인라인 데이터 기반 (항상 실행):
- **다대다** — 같은 키의 결제 3건(-10,000)과 취소 1건(+10,000)이 있을 때, **결제 1건만** 소진된다. 3건 모두 제외되면 실패다
- **시간 역전** — 취소가 결제보다 앞선 경우 짝지어지지 않는다
- **금액 불일치** — 부분 취소(결제 -10,000, 환불 +3,000)는 매칭되지 않는다
- **적요 불일치** — 적요가 다르면 매칭되지 않는다

## 금지사항

- 경과 시간 상한(24시간, "같은 날" 등)을 두지 마라. 이유: 그린카 사례가 42시간이라 놓친다 (DESIGN.md 2.6)
- 취소 쌍을 금액 상쇄로 처리하지 마라. 양쪽을 **제외** 대상으로 표시한다. 이유: 상쇄만 하면 총액은 맞아도 가맹점별 순위가 틀린다 (ADR-005)
- 메모의 `취소` 키워드를 **단독 근거**로 쓰지 마라. 보조 신호로만 허용한다. 이유: 메모는 사용자 자유 입력이라 없을 수 있다
