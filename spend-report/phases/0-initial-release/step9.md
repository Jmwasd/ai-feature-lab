## 작업

업로드 화면과 리포트 화면을 만든다. 한 페이지(`src/app/page.tsx`)에서 상태로 전환한다.

### 화면 구성 — `/docs/UI_GUIDE.md`의 "화면 구성" 절이 정본이다

두 화면을 한 페이지(`src/app/page.tsx`)에서 상태로 전환한다.

**1. 랜딩** (업로드 전)

```
다크 히어로 (bg-ink)
  좌: 배지 → h1 60px/400/-1.6px → 설명 18px → 업로드 드롭존 → "샘플 리포트 열어보기" 링크
  우: 겹친 카드 2장 (bg-surface-dark) — 뒤 카드 rotate(4deg), 앞 카드에 52px 파란 비율 + 6칸 막대
밝은 섹션
  h2 "은행 앱이 말해주지 않는 것" → 2×2 카드 (01~04 순번 + 제목 + 설명) → 하단 Primary 버튼(대)
```

드롭존 안에 **변환 안내 3단계**를 넣는다 (DESIGN.md 5.3의 0번):
① 토스뱅크에서 받은 `.xlsx`를 엑셀·넘버스·구글시트로 연다 ② 비밀번호를 입력한다 ③ `CSV`로 내보낸 뒤 그 파일을 올린다.
사용자가 `.xlsx`를 고르면 업로드하지 말고 **즉시 이 안내를 띄운다.**

**2. 리포트** — 이 순서를 바꾸지 마라

```
헤더        배지 2개 → "계좌 · 기간" 13px → h1 52px | 우측 [다시 업로드] [PDF로 내보내기]
요약 스트립  총 지출 / 거래 건수 / 자동 제외된 취소
            3칸 그리드 1.4fr 1fr 1fr을 테두리 하나로 감싼다. 카드 3장으로 쪼개지 마라
            + 아래 13px 각주: 2인 공동 계좌 합계 고지 (DESIGN.md 4.8)
발견  h2 "네 가지 사실"   ← 주인공
  1  반복 결제    다크 카드(bg-ink) 전폭 · 좌 텍스트 + "월 → 연간" 대비 / 우 반복 리스트
  2  이벤트 묶음   밝은 카드 · 총액 36px + 항목 리스트      ┐ 2열 그리드
  3  지출 집중도   밝은 카드 · 파란 비율 36px + 상위 3개 바  ┘
     └ 2·3 아래에 **중복 계상 고지** — 상위 3건 중 2건이 이벤트에 이미 포함돼 있다 (DESIGN.md 5.2)
  4  미분류 비중   밝은 카드 전폭 · 좌 비율 44px / 우 보정 가능한 행 리스트
AI 요약      발견 바로 아래. `summary`가 `null`이면(API 키 없음) **섹션 자체를 렌더하지 않는다**
분류  h2 "카테고리별 소비"   전폭 카드 · 가로 바 목록 + 하단 분류 규칙 각주
푸터 노트    bg-fill-quiet / radius 24px
            · 기간 한계 고지 (`report.notes`)
            · 데이터 처리 고지 — "업로드 파일은 저장되지 않으며, 분류되지 않은 가맹점명은 OpenAI로
              전송된다. 금액·계좌번호·성명은 전송하지 않는다" (DESIGN.md 5.3-7)
            · Dark 버튼
```

**이벤트는 발견 안의 2번 카드다. 별도 섹션으로 빼지 마라.** DESIGN.md 5.3이 나열한 7개 요소(요약·발견·카테고리·이벤트·AI 요약·기간 한계·데이터 처리)는 위 배치에 **전부 들어가 있다** — 이벤트는 발견 2번, 기간 한계와 데이터 처리는 푸터 노트다.

**발견이 카테고리별 소비보다 위에 온다.** 이 순서가 이 제품의 정체성이다 (PRD 목표).

### 컴포넌트 (`src/components/`)

- `Landing` — 다크 히어로 + 겹친 카드 + 2×2 카드
- `UploadPanel` — 드롭존 + 변환 안내 3단계 + `.xlsx` 감지
- `ReportHeader` — 배지·기간·h1·액션 버튼
- `SummaryStrip` — 3칸 스트립 + 공동 계좌 각주
- `FindingsSection` — 발견 4개 카드 + 중복 계상 고지
- `CategoryTable` — 가로 바 목록 + 분류 규칙 각주
- `FooterNote` — 기간 한계 고지 + 데이터 처리 고지

### 표시 규칙

- **통화는 `₩` 접두 + 천 단위 쉼표.** `₩122,390` 형식이다. **`원` 접미를 쓰지 마라** (UI_GUIDE 타이포그래피)
- 비율은 소수점 없이 정수 `%`로 반올림한다 (`27%`)
- 금액·비율·건수·순번은 **JetBrains Mono(`font-mono`) weight 500** + `tabular-nums`. 그 외 텍스트는 Inter
- **제목은 400이다.** 큰 글자를 굵게 만들지 마라 — 크기와 음수 자간이 위계를 만든다. 600은 18~24px 구간에서만 쓴다
- 색은 step 0에서 `@theme`에 등록한 토큰만 쓴다. **Tailwind 기본 팔레트(`text-neutral-400` 등)나 임의 hex(`bg-[#0052ff]`)를 쓰지 마라** (UI_GUIDE 색상)
- 카테고리 바 색은 **순위 고정**이다. 1위 `#0052ff` / 2위 `#0a0b0d` / 3위 `#2a2d33` / 4위 `#5b616e` / 5위 `#7c828a` / 6위 `#a8acb3` / 7위 `#c9cdd3`. 색이 순위를 나타내므로 임의로 섞지 마라
- `displayName`을 쓴다. **적요 원문을 그대로 노출하지 마라** — PG 이름이 보이면 실패다 (DESIGN.md 5.2)
- 미분류·`알 수 없음`을 회색으로 흐리지 마라. 본문 크기로 적는다 (UI_GUIDE 원칙 3)
- 취소로 제외된 건은 `line-through` + `text-text-muted`
- 컨테이너 폭 **1000px**, 좌우 padding 24px. `max-w-3xl` 같은 좁은 폭을 쓰지 마라
- 카드 라운딩은 **24px로 통일**한다. 버튼은 전부 `border-radius: 100px` — 사각 버튼을 만들지 마라
- 좌측 정렬 기본. 숫자 열만 우측 정렬. 중앙 정렬 금지

## 금지사항

- 카테고리 파이차트를 만들지 마라. 이유: 이 제품이 하지 않기로 한 회고형 표현이다 (UI_GUIDE 안티패턴)
- 섹션 순서를 바꾸지 마라. 발견이 카테고리보다 아래로 가면 제품의 정체성이 사라진다
- 이벤트를 별도 섹션으로 빼지 마라. 이유: UI_GUIDE 화면 구성에서 이벤트는 발견 4개 카드 중 2번이다. 빼면 목업의 2열 그리드가 무너진다
- 금액에 `원` 접미를 쓰지 마라. `₩` 접두다. 이유: UI_GUIDE 타이포그래피가 명시했고 "값이 목업과 다르면 목업이 옳다"
- `text-neutral-*` 같은 Tailwind 기본 색이나 임의 hex를 쓰지 마라. 이유: step 0이 `@theme`에 등록한 무채색 램프 밖의 색이 섞이면 인쇄 대비가 어긋난다
- AI 요약 섹션을 빈 껍데기로 렌더하지 마라. `summary`가 `null`이면 섹션 자체를 빼라. 이유: API 키 없는 상태가 정상 경로다 (ARCHITECTURE.md)
- 적요 원문을 직접 렌더하지 마라. `displayName`을 써라. 이유: `엔에이치엔케이씨피 ㈜`는 사용자가 읽을 수 없다
- 다크모드를 만들지 마라. 이유: 인쇄 산출물이고 두 벌을 관리하면 인쇄 경로가 조용히 깨진다 (UI_GUIDE 색상)
- 사용자 보정 UI를 여기서 만들지 마라. 이유: step 10의 일이다
