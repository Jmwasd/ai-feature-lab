# PRD: spend-report

## 목표

은행 거래내역 CSV에서 **사용자가 몰랐던 소비 사실**을 찾아 한 화면으로 보여준다.

"지난달에 어디에 얼마 썼나"는 카드사·은행 앱이 이미 공짜로 준다. 사용자가 파일을 내려받아 변환하고 업로드하는 수고를 정당화하려면 그 이상이어야 한다.

## 사용자

토스뱅크 계좌를 쓰고, 자기 소비를 직접 뜯어보고 싶은 개인. 공동명의 계좌(2인 생활비 통장) 사용자를 1차 대상으로 상정한다 — 샘플이 그 형태다.

전제: CSV를 직접 내려받아 올릴 의지가 있는 사용자. 그 수고를 감수하지 않는 사람은 이 제품의 대상이 아니다.

## 핵심 기능

1. **CSV 업로드 · 파싱** — 토스뱅크 거래내역 CSV를 읽어 거래 배열로 정규화한다. 헤더 행 자동 탐색, 더미 컬럼 제거, 날짜·금액 정규화
2. **취소 쌍 자동 제외** — 결제 후 취소된 건을 짝지어 양쪽 모두 리포트에서 뺀다. 안 빼면 가맹점별 순위가 틀린다
3. **소비 분류** — 메모 → 키워드 규칙 → LLM → 미분류 순으로 카테고리를 추론한다. 모르면 "미분류"로 남기고 추측하지 않는다
4. **발견 산출** — 반복 결제, 이벤트 묶음(여행 등), 지출 집중도, 미분류 비중
5. **사용자 보정** — 출금과 고액 미상세 건을 사용자가 직접 지정한다. `소비 아님`을 고르면 총액에서 빠지고 재집계된다
6. **PDF 내보내기** — 저장하지 않으므로 새로고침하면 사라진다. 브라우저 인쇄로 파일에 남긴다

## MVP 제외 사항

- **xlsx 직접 업로드** — 토스뱅크 원본은 암호화돼 있어 복호화와 비밀번호 입력이 필요하다. 그 비밀번호는 통상 개인 식별번호라 서버로 받고 싶지 않다 (DESIGN.md 2.8)
- **사람별 리포트** — 공동명의 계좌의 카드 거래에 사용자 구분 필드가 없다. 만들면 두 리포트 모두 빈 껍데기가 된다 (DESIGN.md 4.8)
- **타 은행 포맷** — 토스뱅크에 맞추되, 헤더 탐색과 컬럼명 매칭을 느슨하게 짜서 나중에 매핑 UI를 얹을 여지만 남긴다
- **다중 파일 업로드 · 기간 비교** — 파일 1개, 한 기간만 다룬다
- **로그인 · 데이터 저장 · 이력 관리** — 저장하지 않는 것이 설계 전제다
- **예산 설정 · 목표 관리 · 알림** — 발견형 리포트지 가계부가 아니다

## 디자인

- **인쇄 가능한 리포트.** 대시보드가 아니라 한 장으로 뽑아 남기는 문서다. 밝은 배경 고정, 다크모드 없음 (DESIGN.md 4.12)
- 무채색 기반 + 포인트 1가지. 금액의 부호와 미분류 표시에만 색을 쓴다
- 숫자가 주인공이다. 모든 금액은 `tabular-nums`로 자릿수를 맞춘다
- 차트는 발견을 보조할 때만 쓴다. 파이차트로 카테고리를 나열하는 것은 이 제품이 하지 않기로 한 회고형 표현이다
