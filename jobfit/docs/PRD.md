# PRD: jobfit

## 목표

채용공고를 읽을 때 진짜 알고 싶은 "내 이력서를 고쳐서 메울 수 있는 칸이 어디냐"에 답한다.

## 사용자

나 하나. 로컬에서 `next dev`로 띄워 쓴다. 배포하지 않고 남에게 열어주지 않는다.

## 세 가지가 전부다

1. 채용공고 **링크**를 던진다
2. **Notion에 등록된 이력서**와 대조한다
3. LLM이 **부족한 부분**을 분석해준다

이 셋에 직접 기여하지 않는 것은 전부 뺐다.

## 핵심 기능

1. **공고 링크 본문 추출** — 서버에서 URL을 fetch하고 Readability로 본문을 뽑는다. 실패하면 붙여넣기 textarea로 떨어진다
2. **Notion 이력서 읽기** — 블록 트리를 재귀 순회해 `회사 > 프로젝트` 소속이 붙은 근거 목록을 만든다
3. **3분할 분석** — 요구사항을 `갖춘 것 / 안 쓴 것 / 없는 것`으로 가르고, 각 항목에 Notion 원문 근거를 붙인다
4. **고쳐 쓴 문장 제안** — "안 쓴 것"에 공고 용어로 표현만 바꾼 문장과 복사 버튼을 준다

| 칸 | 정의 | 산출물 |
|---|---|---|
| 갖춘 것 (`covered`) | 이력서에 근거 블록이 있다 | 근거 표시 |
| 안 쓴 것 (`implicit`) | 근거는 있는데 공고의 용어로 안 적혀 있다 | 다시 쓴 문장 제안 |
| 없는 것 (`missing`) | 근거가 없다 | 그대로 표시 |

**두 번째 칸이 이 제품의 존재 이유다.** "GitHub Actions로 배포 자동화"라고 적은 사람이 "CI/CD 구축 경험"을 요구하는 공고 앞에서 자기에게 없다고 판단하는 상황을 잡아낸다.

## MVP 제외 사항

- 분석 결과 저장 (새로고침하면 사라진다)
- 여러 공고에 걸친 누적 갭 집계·순위
- 이력서 편집 화면 — Notion에서 직접 고친다
- 자기소개서·커버레터 생성
- 계정·로그인·서버 저장
- 이력서 파일 업로드(PDF/DOCX 파싱)
- 신원 정보 마스킹 — 내 키로 내 이력서만 보내므로 수혜자가 나 하나다. **배포하게 되면 이 규칙을 처음부터 다시 세워야 한다**

## 화면

페이지 하나(`/`)다. 저장이 없으므로 라우트를 나눌 이유가 없다.

```
[랜딩]  도구 설명 한 줄 + 공고 링크 입력 + [분석]
   ↓  (본문 추출 실패 시) 붙여넣기 textarea가 열린다
[결과]  갖춘 것 / 안 쓴 것 / 없는 것 3칸
```

- 각 항목에 근거 블록 텍스트를 Notion 원문 그대로 표시하고 소속을 `회사 > 프로젝트`로 붙인다
- `must` / `nice`를 항목에 표시한다. 어느 갭부터 메울지는 이것으로 갈린다
- `requiredMonths`가 있으면 "요구 경력 3년" 배지를 붙인다. **내 경력 개월 수는 계산하지도 표시하지도 않는다**
- 판정마다 신뢰도를 함께 보여준다. 이것은 모델의 자기평가라 보정된 확률이 아니고 "검토 필요" 신호로만 쓴다
- 첫 분석 전에 **이력서 원문과 공고 본문이 OpenAI API로 전송된다는 사실**과 Notion 읽기 범위를 짧게 알린다

## 디자인

`docs/UI_GUIDE.md`를 따른다. 요지는 셋이다.

- 도구처럼 보인다. 마케팅 페이지가 아니다
- 무채색 + 포인트 한 가지. 그 포인트는 **"안 쓴 것" 칸에만** 쓴다
- 근거 원문이 제안보다 먼저 읽혀야 한다
