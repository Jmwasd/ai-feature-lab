# UI 디자인 가이드

이 문서는 **진입점**이다. 원칙과 결정 이력만 담고, 구체적인 수치는 담지 않는다.

## UI를 건드릴 때

코드를 쓰기 전에 이 문서의 원칙을 읽고, **`.claude/skills/jobfit-design/SKILL.md`에서** 색·크기·간격·컴포넌트 규격을 확인하라.

Claude Code 세션에서는 `jobfit-design` 스킬이 자동으로 걸리지만, 하네스(`codex exec`)는 스킬을 모른다. **하네스로 UI step을 태울 때는 step 파일의 "읽어야 할 파일"에 이 문서, `SKILL.md`, `references/tokens.css`를 명시하라.**

## 디자인 원칙

규격은 바뀔 수 있지만 원칙은 아니다. 아티팩트를 다시 뽑아도 이 넷은 유지된다.

1. **도구처럼 보여야 한다.** 마케팅 페이지가 아니라 공고를 볼 때마다 여는 작업창이다. 히어로 섹션도, 소개 문단도, 로고 그래픽도 없다.
2. **주목을 "안 쓴 것"에 몰아준다.** 유채색은 이 앱 전체에서 한 가지뿐이고, 그 한 가지를 `implicit` 칸에만 쓴다.
   - **Why:** 이 도구가 존재하는 이유가 두 번째 칸이다. 세 칸에 각각 색을 주면 신호등이 되고 강조가 사라진다.
3. **근거 원문이 제안보다 먼저 읽혀야 한다.** 제안은 LLM이 쓴 문장이고 근거는 내가 쓴 문장이다. 위치·크기·순서 모두에서 근거가 앞선다.
4. **색이 아니라 밀도로 가른다.** 세 칸의 차이는 구조다 — `covered`는 테두리 카드, `implicit`은 포인트 색 카드 + 제안 구획, `missing`은 카드가 아니라 밑줄 행이다.

## 결정 이력

### 아티팩트를 기준으로 삼으면서 뒤집힌 것 (2026-08-31)

이 문서의 초판은 아티팩트 없이 쓰였다. 아트보드가 나오면서 아래가 바뀌었다. **원칙은 하나도 바뀌지 않았고 값만 갈렸다.**

| 항목 | 이전 | 지금 |
|---|---|---|
| 명도 | 다크 고정 | 라이트 |
| 포인트 색 | amber | coral |
| 폰트 | 시스템 폰트, 웹폰트 금지 | Space Grotesk · Inter · IBM Plex Mono |
| 버튼 모서리 | 통일 | 역할별로 다름 |
| `covered`의 근거 | 접어두고 "근거 보기" | 처음부터 펼침 |

**웹폰트 금지를 뒤집은 이유:** 이 도구는 배포하지 않고 로컬에서만 돈다. 폰트 세 벌의 로딩 비용을 아낄 대상이 나 하나뿐이고, 그 대신 mono 라벨이 본문과 확실히 갈려서 "이건 데이터가 아니라 라벨"이 한눈에 읽힌다.

**다크를 버린 이유:** 개인 도구 하나에 팔레트를 두 벌 유지할 이유가 없다. 초판이 다크를 고른 것도 같은 논리(한 벌만 유지)였고, 아트보드가 라이트로 나왔으니 그쪽 한 벌만 남긴다.

## 값을 바꾸는 법

아티팩트를 고치고 아트보드를 다시 뽑아 `references/`를 갱신한 뒤 `SKILL.md`를 맞춘다.

**이 문서에 수치를 적지 마라.** 초판이 수치를 들고 있다가 `SKILL.md`와 34개가 겹쳤다. 사본이 둘이면 어느 쪽이 최신인지 알 수 없다.
