jobfit의 변경 사항을 리뷰하라. `jobfit/` 밖의 파일은 보지 않는다.

먼저 다음 문서들을 읽어라:

- `CLAUDE.md`
- `docs/PLAN.md` (설계 근거 전문. 다른 문서와 충돌하면 이것이 우선이다)
- `docs/ARCHITECTURE.md`
- `docs/ADR.md`
- `docs/UI_GUIDE.md` (UI가 바뀐 경우)

그런 다음 변경된 파일들을 확인하고, 아래 체크리스트로 검증하라.

## 체크리스트

### 공통

1. **아키텍처 준수** — ARCHITECTURE.md 디렉토리 구조와 레이어 방향을 따르는가? (`app → services → 외부`, `lib`은 아무것도 import 하지 않는 잎)
2. **기술 스택 준수** — ADR의 결정을 벗어나지 않았는가?
3. **테스트 존재** — `src/lib/`의 새 순수 함수에 테스트가 있는가? (UI는 요구하지 않는다)
4. **빌드 가능** — `npm run lint && npm run build && npm run test`가 통과하는가?

### jobfit CRITICAL

5. **근거 앵커링** — LLM이 근거 문장을 쓰지 않는가? 블록 ID만 받고 텍스트는 코드가 Notion 원문에서 가져오는가? 실재하지 않는 blockId를 버리는가?
6. **비밀값 격리** — `OPENAI_API_KEY`·`NOTION_TOKEN`이 Route Handler 밖에서 읽히거나 `NEXT_PUBLIC_*`에 들어가지 않았는가?
7. **`lib` 순수성** — `src/lib/`에 React·Next·네트워크·프롬프트 import가 들어가지 않았는가? 집계·검증이 LLM이 아니라 순수 함수에 있는가?
8. **저장 없음** — IndexedDB·서버 DB·파일 캐시가 새로 생기지 않았는가?
9. **프롬프트 위치** — 프롬프트가 `src/prompts/` 파일에 있고 코드에 인라인되지 않았는가?
10. **누락 처리** — LLM 응답 누락을 `missing`으로 간주하지 않고 "판정 없음"으로 남기는가?
11. **경력 계산 금지** — 내 경력 개월 수를 계산·표시하는 코드가 들어가지 않았는가?
12. **UI 안티패턴** — UI_GUIDE.md 금지 표를 어기지 않았는가? 포인트 색(amber)이 `implicit` 밖에서 쓰이지 않았는가?
