# UI 디자인 가이드

> UI가 있는 프로젝트에서만 사용하는 디자인 규칙의 단일 원본이다.
> 다른 문서나 step 파일에 이 내용을 복제하지 않는다.

## 톤

터미널 옆에 띄워두고 오래 들여다보는 개발자 도구. 어두운 배경, 높은 정보 밀도, 장식 최소. 라이트 모드는 만들지 않는다 — 토큰을 두 벌 유지하지 마라.

## 색 (Tailwind 임의 값 대신 아래 토큰을 쓴다)

`globals.css`의 `:root`에 CSS 변수로 정의하고 `tailwind.config.ts`에서 이름을 연결한다.

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `bg` | `#0d1117` | 페이지 배경 |
| `surface` | `#161b22` | 카드, 패널 |
| `border` | `#30363d` | 경계선 |
| `text` | `#e6edf3` | 본문 |
| `muted` | `#8b949e` | 날짜, 보조 설명, 라벨 |
| `accent` | `#58a6ff` | 링크, 포커스 링, 선택 상태 |
| `add` | `#3fb950` | 추가된 줄, `+` 숫자 |
| `del` | `#f85149` | 삭제된 줄, `-` 숫자, 에러 |

추가·삭제 색은 diff와 숫자 지표에서만 쓴다. 버튼이나 배경에 쓰지 마라.

## 타이포

- 본문·UI: 시스템 sans-serif 스택.
- **해시, 파일 경로, diff 본문, 숫자 지표는 반드시 모노스페이스**(`ui-monospace, SFMono-Regular, Menlo, monospace`).
- 크기는 `text-sm`(14px)을 기본으로 한다. 본문에 `text-base` 이상을 쓰지 마라 — 한 화면에 들어가는 커밋 수가 줄어든다.
- 커밋 해시는 앞 7자만 노출한다.

## 레이아웃

- 최대 폭 `max-w-5xl`, 가운데 정렬, 좌우 여백 16px.
- 카드 사이 간격 8px, 카드 안쪽 패딩 12px 16px. 여백으로 숨 쉬게 하지 말고 경계선으로 구분한다.
- 상단 바는 고정(`sticky top-0`)이며 저장소 이름과 계정 아바타·로그아웃만 둔다.

## 컴포넌트 규칙

- **지표 4종**: 한 줄에 4칸, 좁은 화면에서는 2×2. 숫자는 모노스페이스 `text-2xl`, 라벨은 `muted` `text-xs` 대문자.
- **커밋 카드**: 한 줄에 제목(넘치면 말줄임), 그 아래 줄에 `muted`로 날짜 · 파일 N개 · `+추가` `-삭제`. 카드 전체가 클릭 대상이고 hover 시 `border`가 `accent`로 바뀐다. 커밋 하나당 정확히 한 장이다.
- **diff**: 파일별 접이식 패널. 기본은 펼침, 300줄을 넘는 파일은 접힌 채로 시작한다. 추가 줄은 `add` 배경 10%, 삭제 줄은 `del` 배경 10%, 줄 번호는 `muted`. 구문 강조는 하지 않는다.
- **요약 블록**: 상세 페이지 맨 위, `surface` 배경에 왼쪽 `accent` 세로선. 로딩 중에는 스켈레톤 3줄. 실패하면 이 블록만 한 줄 안내로 접히고 아래 diff는 그대로 보인다. diff가 잘렸으면 블록 하단에 `muted` `text-xs`로 그 사실을 적는다.
- **빈 상태·에러**: 가운데 정렬 카드 한 장에 무슨 일인지, 지금 경로가 무엇인지, 어떻게 고치는지 세 줄. 아이콘이나 일러스트는 쓰지 않는다.
- **랜딩**: 상단에 제품명과 한 줄 소개, 그 아래 기능 3개를 카드로, 그 아래 구글 로그인 버튼. GIS 버튼은 구글이 렌더하므로 스타일을 덮어쓰지 말고 `surface` 위에 그대로 올린다.
- **더 보기**: 목록 맨 아래 폭 100% 버튼. 불러오는 동안 비활성 + "불러오는 중". 무한 스크롤을 쓰지 마라.

## 접근성

- 포커스 링은 지우지 않는다(`accent` 2px).
- 색으로만 뜻을 전하지 않는다 — diff 줄은 색과 함께 `+`/`-` 기호를 남긴다.
- 클릭 대상은 카드든 버튼든 최소 높이 40px.
