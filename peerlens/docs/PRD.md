# PRD: PeerLens M0

## 목표

초기 지원하는 S&P 500 종목 50개 중 하나를 검색하면, 그 종목과 관련된 종목을 **최대 5개** 보여준다. 각 결과에는 사업상 관련 근거 한 줄, 분기 매출 성장률 상관계수, 표본 수를 붙인다.

M0가 검증할 질문은 하나다. **사용자가 이 관련주 결과를 유용하다고 느끼는가?** 재무 정보 포털이나 AI 리포트 제품을 만드는 단계가 아니다.

## 사용자

미국 주식에 투자하는 한국 개인투자자(서학개미) 중 종목 발굴 시간을 줄이고 싶은 중급자.

- 영문 사업 설명을 빠르게 이해하고 싶은 사람
- 숫자를 보고 관련성의 강도를 직접 판단하려는 사람
- 수치가 없거나 표본이 부족할 때 그 사실을 명확히 보려는 사람

## 성공 기준

M0에는 계정·로그인·분석 리포트가 없으므로 가입 수를 성공 지표로 사용하지 않는다. 지원 종목을 직접 써 본 초기 사용자에게서 관련주 결과에 대한 정성 피드백을 수집하고, 그 결과로 전체 S&P 500 확대와 M1 기능의 필요성을 판단한다.

이전의 “이메일 가입 30명” 목표는 M1에서 로그인 기반 리포트를 실제로 도입하기로 결정했을 때 다시 활성화한다.

## 핵심 기능

1. **종목 검색** — 초기 지원 50개 종목의 티커/회사명 자동완성.
2. **관련주 최대 5개 제시** — 사업 관계 근거 한 줄, 분기 매출 성장률 상관계수, 표본 수를 함께 표시. 후보가 품질 기준을 충족하지 않으면 5개를 억지로 채우지 않는다.
3. **작은 비교표** — 검색 종목과 관련주에 대해 최신 분기 매출, 전년 동기 대비 매출 성장률, 최근 연간 영업현금흐름만 비교한다.
4. **데이터 한계 표시** — 표본이 8분기 미만이면 상관계수 대신 “표본 부족”, XBRL 값이 없으면 “데이터 없음”을 표시한다.

상관계수는 매출 성장의 동행 정도를 보여 주는 보조 지표다. 사업 관계를 인과적으로 증명하거나 투자 판단을 검증하는 값으로 표현하지 않는다.

## 사용자 흐름

```
랜딩 → 종목 검색 → 종목 상세(관련주 최대 5개 + 작은 비교표) → 관련주 클릭 → 해당 종목 상세
```

모든 화면은 로그인 없이 열람한다. 검색 결과는 사전생성된 정적 데이터를 읽기 때문에 외부 API 호출과 LLM 호출이 없다.

## 데이터 갱신

- 최초 데이터와 이후 갱신은 개발자가 수동으로 실행하는 배치로 만든다.
- 대상은 초기 50개이며, SEC EDGAR에서 분기 매출 시계열과 3개 비교 지표만 수집한다.
- LLM은 수동 배치에서 관련주 후보와 근거를 만들 때만 사용한다. 후보 티커를 지원 종목 목록과 대조한 뒤 후보 쌍의 상관계수만 계산한다.
- 화면에는 데이터 기준일을 표시한다. 일일 크론과 자동 갱신은 M0에 넣지 않는다.

## M0 제외 사항

- **S&P 500 전체 커버리지** — 초기 50개 결과의 품질 검수 후 확대한다.
- **주가·시세 데이터 일체** — 주가 차트, 실시간/지연 시세, 주가 상관계수.
- **8~10개 재무 지표, 5년 추이, 9개 선 오버레이 차트** — 관련주 가설 검증에 필요한 최소 정보가 아니며, XBRL 정규화와 UI 복잡도만 크게 늘린다.
- **모든 종목쌍 상관계수 사전 계산** — LLM 후보 종목쌍만 계산한다.
- **AI 심층 분석 리포트, 10-K 섹션 파싱, 로그인, 사용량 제한, 프로필** — 관련주 결과가 유용하다는 신호를 얻은 뒤 M1에서 별도로 판단한다.
- **결제·구독, 테마 키워드 검색, 자연어 질문, 한국 주식, S&P 500 외 미국 종목, 뉴스 요약, 라이트모드, 봇 방어**.

## 디자인

- 다크모드 고정, 데이터 밀도 우선, 무채색 기반.
- 양수/성장은 녹색, 음수/감소는 빨강으로만 표시한다.
- 상관계수와 표본 수, 데이터 기준일을 항상 같이 보여 준다.
- 상세 규칙은 `UI_GUIDE.md`를 따른다.

## 법적 포지셔닝

- 서비스는 공개 공시 데이터와 사업 관계를 정리한 정보 제공 화면이다.
- 매수·매도 의견, 목표가, 수익 보장을 제시하지 않는다.
- 면책 문구는 제공하되, 그것만으로 법적 의무가 사라진다고 단정하지 않는다.
- 유료화·개별 상담·리포트 기능을 도입하기 전에는 해당 시점의 규제와 서비스 구조를 별도로 검토한다.
