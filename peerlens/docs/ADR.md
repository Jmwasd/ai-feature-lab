# Architecture Decision Records

## 철학

**MVP 속도 최우선. 라이선스가 깨끗한 데이터만 쓴다. 검증할 수 없는 주장은 화면에 올리지 않는다.**

- 이 제품의 유일한 난이도이자 유일한 차별점은 "관련주를 어떻게 찾느냐"다. 랜딩·로그인·배포는 기성 부품으로 조립하고, 아낀 시간을 전부 관련주 품질에 넣는다.
- 외부 의존성은 최소화한다. 데이터 소스가 하나(SEC EDGAR) 늘어날 때마다 라이선스·레이트리밋·장애 표면이 함께 늘어난다.
- 비용은 사용자 수가 아니라 **종목 수에 비례**하도록 설계한다. 그래야 트래픽이 늘어도 예산이 터지지 않는다.

### ADR-001: 미국 주식 S&P 500 단일 시장

**결정**: 대상 시장을 미국 주식으로 하되, 커버리지는 S&P 500 종목으로 한정한다.
**이유**: SEC EDGAR가 재무 데이터를 무료·합법·무제한에 가깝게 제공해 데이터 비용이 0이 된다. 500종목이면 전 종목 사전 계산이 하루 안에 끝나 검색이 항상 즉시 응답한다.
**트레이드오프**: 한국 주식을 포기했다(관련주/테마주 니즈는 한국 시장이 더 뾰족하다). S&P 500 밖 종목을 검색한 사용자는 결과를 받지 못한다. 미국 시장에는 이미 Finviz·Koyfin·stockanalysis.com 같은 강력한 무료 경쟁자가 있어, 재무·차트만으로는 차별화가 불가능하다 — 그래서 관련주가 유일한 승부처다.

### ADR-002: 시세 데이터를 사용하지 않는다

**결정**: 주가·시세 데이터를 일절 쓰지 않는다. 주가 차트와 주가 상관계수를 제품에서 제외한다.
**이유**: 무료 시세 API는 데이터의 웹 표시를 재배포로 간주해 금지한다. Tiingo 무료 티어는 "internal and personal use only, may not be redistributed in any form"이며 재배포 사례로 "a website or app"을 명시적으로 열거한다. 유료 Commercial 플랜조차 재배포는 별도 협의 대상이다. 약관을 위반한 상태로 공개 서비스를 운영할 수 없다.
**트레이드오프**: 원래 관련주 검증 축이던 주가 상관계수를 잃었다(→ ADR-003으로 대체). 사용자가 기대할 법한 주가 차트가 없다. 다만 EDGAR만 쓰면 데이터 비용이 0이고 법적 리스크도 0이 된다.

### ADR-003: 관련주 = LLM 후보 생성 + 분기 매출 성장률 상관 검증

**결정**: Claude가 근거 한 줄과 함께 관련주 후보를 제시하고, 종목 마스터 대조로 환각을 거른 뒤, **분기 매출 성장률 상관계수와 표본 수**를 함께 표시한다.
**이유**: LLM 단독은 환각을 검증할 수단이 없어 신뢰를 얻지 못한다. 매출 상관은 주가 상관보다 오히려 본질적이다 — 주가 상관은 시장 전체 등락(베타)에 오염되지만, 매출 상관은 **사업이 실제로 연동되는지**를 직접 보여준다. "주가가 같이 움직인다"보다 "매출이 같이 움직인다"가 훨씬 강한 주장이고, 데이터는 EDGAR에서 무료로 나온다.
**트레이드오프**: 5년치라도 분기는 20개뿐이라 통계적 신뢰도가 낮다. 상장 이력이 짧은 종목은 더 적다. 표본 수를 항상 병기하고 8분기 미만이면 수치를 숨겨 완화하되, 이 약점을 UI에서 감추지 않는다. 또한 분기 공시 주기에 묶여 갱신이 느리다.

### ADR-004: 결제를 만들지 않는다. 전면 무료

**결정**: 결제·구독·플랜을 구현하지 않는다. 관련 스키마와 코드를 **아예 남기지 않는다.**
**이유**: 한국 거주자에게 유료로 주식 분석을 제공하면 자본시장법상 유사투자자문업 신고 대상이 될 수 있고, 사업자 지위·PG 계약·환불정책이 전부 선결 과제가 된다. 무료면 "대가를 받고 투자판단을 조력"하는 구조가 아니어서 규제 표면이 사실상 사라진다. 검증 단계에서 결제 구현에 1~1.5주를 쓰는 것보다 관련주 품질에 쓰는 편이 낫다.
**트레이드오프**: 지불 의사를 직접 확인할 수 없어 성공 지표를 이메일 가입 30명이라는 대리 지표로 대체했다. 그리고 **결제라는 자연스러운 비용 방어선이 사라져** 별도의 사용량 상한 설계가 필요해졌다(→ ADR-009, ADR-010). 나중에 유료화하려면 이 ADR과 규제 판단을 함께 다시 열어야 한다.

### ADR-005: 관련주는 사전생성, 리포트는 온디맨드 + 영구 캐시

**결정**: 관련주 매핑은 500종목 전체를 배치로 미리 생성해 DB에 넣는다. AI 리포트는 요청 시 생성하고 **종목 단위로 영구 캐시**해 모든 사용자가 공유한다.
**이유**: 무료로 공개하는 검색 경로는 지연이 0이어야 하고, 관련주 사전생성은 1회 $2~5로 저렴하다. 반면 리포트는 10-K를 입력해야 해 건당 $0.25로 비싸므로 실제로 요청된 종목만 만든다. 캐시가 종목 단위이므로 **총비용이 사용자 수가 아니라 고유 종목 수에 비례**한다.
**트레이드오프**: 처음 열람하는 종목의 사용자는 생성 대기를 겪는다. 500종목을 전부 미리 굽는 선택(약 $62.5, Batch API 기준)도 있었으나, 아무도 안 볼 400개 종목에 선결제하는 셈이라 택하지 않았다.

### ADR-006: 리포트 생성에 Claude Opus 5 사용

**결정**: `claude-opus-5`를 쓴다. 리포트 1건은 10-K 핵심 섹션 약 40k 토큰 입력 + 2k 출력 = 약 $0.25.
**이유**: 리포트는 이 제품에서 유일하게 "유료급 자산"에 해당하는 산출물이고, 10-K 해석 품질이 곧 제품 신뢰도다. 캐시가 종목 단위로 영구 공유되므로 건당 단가가 총비용을 좌우하지 않는다 — 총비용은 고유 종목 수로 결정된다.
**트레이드오프**: Sonnet 5($0.15) 대비 건당 67% 비싸다. 전역 상한 20건/일 기준 월 최대 $150으로, 인프라 비용 $0을 감안해도 예산의 대부분을 여기서 쓴다.

### ADR-007: 10-K 전문이 아니라 핵심 섹션만 입력

**결정**: 10-K에서 Item 1(사업), Item 1A(리스크 요인), Item 7(MD&A)만 추출해 LLM에 넣는다.
**이유**: 10-K 전문은 100k~200k 토큰이라 리포트 1건이 $0.6~1.2로 뛰어 누적 예산이 3~5배가 된다. 세 섹션이 사업 이해·리스크·실적 해석의 대부분을 담고 있고, EDGAR 문서는 Item 제목 형식이 일정해 정규식으로 잡을 만하다.
**트레이드오프**: 섹션 파싱 코드가 필요하고, 형식이 특이한 기업에서는 추출이 실패할 수 있다. 재무제표 주석 등 다른 섹션의 정보는 리포트에 반영되지 않는다.

### ADR-008: Next.js App Router + Vercel Hobby

**결정**: Next.js App Router로 만들고 Vercel Hobby(무료) 플랜에 배포한다.
**이유**: 랜딩은 정적 생성으로 SEO를 확보하고, API 키는 서버 라우트에 숨기고, 일일 배치는 Vercel Cron으로 돌리고, 배포는 git push 하나로 끝난다. 혼자 3~4주 일정에서 관리할 프로세스가 하나로 줄어든다. Hobby 크론의 1일 1회·UTC 고정 제약은 EDGAR 공시 데이터를 하루 한 번 받는 용도에 아무 문제가 없다.
**트레이드오프**: 크론 실행 시각을 정확히 지정할 수 없고(지정한 시 내에서 분산), 분기 배치는 수동 실행해야 한다. Hobby의 상업적 이용 조항은 무료 서비스인 동안에는 문제되지 않지만, 수익화 시 Pro($20/월)로 올려야 한다.

### ADR-009: 로그인 벽은 AI 리포트에만 세운다

**결정**: 검색·관련주·재무·차트는 로그인 없이 무제한 공개한다. AI 리포트만 로그인을 요구하고, 첫 문단 미리보기 후 나머지를 블러 처리한다.
**이유**: 검색 경로는 전부 DB 조회라 LLM 호출이 0이고 비용도 0이므로, 제한할 이유가 없다(결제 시절 계획했던 "검색 하루 3회 제한"은 이 결정으로 폐기됐다). 전면 공개는 SEO와 공유에도 유리하다. 리포트는 실제로 돈이 드는 유일한 기능이므로 여기에만 벽을 세운다. 미리보기로 내용의 질을 먼저 보여줘야 이메일을 낼 이유가 생긴다.
**트레이드오프**: 가입 트리거가 리포트 하나로 좁아졌다. 대부분의 방문자가 가입 없이 떠나므로, 성공 지표(가입 30명)를 채우려면 리포트 미리보기의 설득력이 전부를 결정한다.

### ADR-010: 전역 일일 상한을 최종 비용 방어선으로 삼는다

**결정**: 리포트 신규 생성을 **계정당 3건/일 + 전역 20건/일**로 제한한다. 봇 방어나 이메일 도메인 차단은 하지 않는다.
**이유**: 무료 가입이므로 계정을 여러 개 만들면 계정별 제한은 무력화된다. 전역 상한은 계정 수와 무관하게 지출 상한을 물리적으로 보장한다(최대 월 $150). 추가 구현이 0이고, 남용의 피해는 "그날 마감이 일찍 뜨는 것"뿐이다.
**트레이드오프**: 상한이 소진된 날에는 신규 방문자가 리포트를 볼 수 없어 **그날의 가입 전환이 막힌다** — 유입이 몰리는 날일수록 정확히 그 순간에 걸린다. 완화책으로 상한 도달 후에도 이미 캐시된 리포트는 계속 열람 가능하게 한다.

### ADR-011: 데이터 결손을 추론으로 채우지 않는다

**결정**: EDGAR XBRL 태그가 없어 지표를 못 뽑으면 해당 칸에 **"데이터 없음"**을 명시한다. 대체 태그로 추론해 채우지 않는다. 상관계수 표본이 8분기 미만이면 수치를 숨긴다.
**이유**: 회사마다 계정과목 태그가 달라 누락은 상시 발생한다. 대체 태그 매핑은 커버리지를 올리지만 매핑이 틀리면 **틀린 숫자를 자신 있게 보여주게 된다.** 금융 데이터에서 조용히 틀린 값은 신뢰를 한 번에 잃는 가장 빠른 길이다.
**트레이드오프**: 표가 군데군데 비어 완성도가 떨어져 보인다. 비교표의 유용성도 일부 손상된다.

### ADR-012: 정보 제공 포지셔닝 (규제 대응)

**결정**: 투자자문이 아닌 정보 제공 서비스로 포지셔닝한다. AI 출력을 데이터 요약·비교로 한정하고 매수/매도 의견과 목표가를 **프롬프트 레벨에서 금지**한다. 전 페이지 하단과 이용약관에 면책을 명시한다.
**이유**: 유사투자자문업 신고는 금융당국 신고·교육 이수·보고 의무가 따라와 검증 단계에 과잉이다. 전면 무료(ADR-004)와 결합하면 규제 표면이 사실상 사라지므로, 프롬프트 가드레일과 면책 고지가 현실적이고 충분한 방어선이다.
**트레이드오프**: "이 종목 사야 하나요"에 답하지 않으므로, 그걸 원하는 사용자에게는 밋밋하게 느껴진다. 가장 잘 팔릴 형태의 콘텐츠를 스스로 포기하는 결정이다.

### ADR-013: Supabase (Auth + Postgres) 단일 채택

**결정**: 인증과 데이터베이스를 Supabase 하나로 조달한다.
**이유**: 소셜 로그인이 기본 제공되어 가입 마찰을 최소화할 수 있다(가입 수가 성공 지표이므로 직결된다). 무료 티어로 재무 데이터·상관계수·리포트 캐시를 모두 담을 수 있고, 혼자 3~4주 일정에서 관리 대상이 하나 줄어든다. 실제로 어떤 로그인 수단을 열지는 → ADR-014.
**트레이드오프**: Vercel 외에 벤더가 하나 늘어난다. 무료 티어의 용량·연결 수 제한에 걸리면 이전 비용이 발생한다.

### ADR-014: 로그인은 구글 OAuth 하나만 제공한다

**결정**: 로그인/가입 수단을 **Supabase Auth의 구글 OAuth 단독**으로 한다. 이메일+비밀번호, 매직링크, 그 외 소셜 로그인(GitHub, Apple 등)을 만들지 않는다. 로그인 화면에는 "Google로 계속하기" 버튼 하나만 둔다.
**이유**: 로그인 벽은 AI 리포트 한 곳에만 있고(ADR-009), 그 앞에서 이탈하면 성공 지표(가입 30명)가 그대로 깎인다. 구글 OAuth는 서학개미 대부분이 이미 로그인된 계정을 갖고 있어 **클릭 두 번으로 끝나며**, 매직링크처럼 메일함을 열었다 돌아오는 왕복(리포트 화면을 떠나는 순간이 곧 이탈 지점이다)이 없다. 구현 측면에서도 비밀번호 재설정·이메일 검증·발송 도메인 설정·스팸함 대응이 전부 사라지고, 검증된 이메일 주소는 구글이 보증해서 넘겨준다 — 성공 지표가 "이메일 가입 수"이므로 이 값의 신뢰성이 곧 지표의 신뢰성이다. 수단을 하나로 줄이면 인증 코드 경로도 하나가 되어 3~4주 일정에서 디버깅 대상이 줄어든다.
**트레이드오프**: 구글 계정이 없거나 쓰기 싫은 사용자는 아예 가입할 수 없다 — 그만큼의 잠재 가입자를 포기하는 결정이다. 구글에 벤더 의존이 하나 늘고, OAuth 동의 화면·클라이언트 자격증명 발급이라는 **수동 선결 작업**이 생긴다(harness step 11이 `blocked`로 떨어질 수 있는 지점). 수단을 추가해야 할 근거가 생기면(예: 가입 시도 대비 완료율이 눈에 띄게 낮으면) 매직링크를 다시 여는 것이 첫 후보이며, Supabase 설정 변경 + 버튼 추가 수준이라 되돌리는 비용은 낮다.
