# Architecture Decision Records — M0

## 철학

**관련주 결과의 품질을 먼저 검증한다.** 데이터 플랫폼, 개인화 제품, AI 리포트는 그 결과가 유용하다는 신호를 얻은 뒤에만 추가한다.

### ADR-001: 초기 범위는 S&P 500 중 50개 종목

**결정**: 초기 지원 목록을 수동으로 검수한 50개 종목으로 제한한다.

**이유**: 500개 전체 적재·분기별 LLM 생성·일일 동기화는 검색 결과가 유용한지 확인하기 전에 운영 시스템을 만드는 일이다. 50개면 검색, 데이터 수집, 결과 검수를 실제 서비스 형태로 검증할 수 있다.

**트레이드오프**: 지원하지 않는 S&P 500 티커가 많다. 지원 종목임을 검색과 상세 페이지에서 분명히 표시하고, 품질 검토 후에만 범위를 늘린다.

### ADR-002: 시세 데이터를 사용하지 않는다

**결정**: 주가·시세·주가 상관계수·주가 차트를 제품에 넣지 않는다.

**이유**: 데이터 라이선스와 재배포 검토를 추가하지 않고 SEC EDGAR 공시 데이터 하나로 관련주 가설을 검토한다.

**트레이드오프**: 사용자가 기대할 수 있는 주가 차트가 없다. 이 제품은 가격 화면이 아니라 사업 관계 탐색 화면으로 한정한다.

### ADR-003: 관련주는 후보 생성 후 후보 쌍의 매출 성장률만 검토한다

**결정**: 수동 LLM 배치가 사업 관계 후보를 만들고, 지원 티커인지 확인한 뒤 그 후보 쌍에 대해서만 분기 매출 성장률 상관계수와 표본 수를 계산한다. 결과는 최대 5개다.

**이유**: 모든 50개 종목쌍을 저장·운영할 이유가 없다. 사용자가 보는 후보의 숫자만 계산하면 되고, 고정 8개보다 품질을 우선할 수 있다.

**트레이드오프**: 상관계수는 사업 관계의 인과를 증명하지 않는다. 화면과 근거 문구에서 “검증” 또는 투자 판단 표현을 쓰지 않고, 동행 정도와 표본 수로만 설명한다.

### ADR-004: M0 데이터는 정적 JSON 스냅샷이다

**결정**: `src/data/m0-data.json`을 앱의 읽기 모델로 사용한다. 수집·생성은 개발자가 수동 배치로 실행하고 검토 후 커밋한다.

**이유**: M0에는 쓰기 경로, 사용자별 상태, 실시간 최신성이 없다. Supabase, RLS, 마이그레이션, API Route, Cron을 추가하면 검증 전 운영 표면만 늘어난다.

**트레이드오프**: 데이터가 실시간이 아니며 갱신은 수동이다. 화면에 기준일을 표시하고, 갱신 빈도는 사용성 검증 후에 결정한다.

### ADR-005: 재무 비교는 세 지표만 제공한다

**결정**: 최신 분기 매출, 매출 YoY 성장률, 최근 연간 영업현금흐름만 비교한다. 5년 추이, 8~10개 지표, 다중 선 차트는 만들지 않는다.

**이유**: 관련주 결과를 읽는 데 필요한 최소 맥락은 매출 규모·성장·현금흐름이다. 더 많은 XBRL 매핑은 커버리지 검증과 UI를 크게 복잡하게 한다.

**트레이드오프**: 심층 재무 분석에는 부족하다. 이는 M0의 목적이 아니다.

### ADR-006: 로그인과 AI 리포트는 M1로 미룬다

**결정**: Google OAuth, 10-K 파싱, 온디맨드 LLM 리포트, 캐시, 사용량 상한을 M0에서 제외한다.

**이유**: 이 기능 묶음은 별도의 리서치 제품이며, 로그인 게이트·비용 한도·동시성·개인정보처리방침·OAuth 운영을 함께 요구한다. 관련주 기능의 가치를 확인하기 전에는 과잉이다.

**트레이드오프**: M0에서 가입 전환을 측정하지 않는다. 초기 사용성 피드백으로 다음 투자를 결정한다.

### ADR-007: 법적·호스팅 판단을 단정하지 않는다

**결정**: 매수·매도·목표가·수익 보장을 제공하지 않고, 면책 고지를 둔다. 무료 운영, 면책, 특정 호스팅 플랜만으로 규제나 이용 조건의 위험이 사라진다고 문서화하지 않는다.

**이유**: 무료 여부는 규제 검토의 한 요소일 뿐이며, 사업화·개별 상담·유료화 시의 판단은 서비스 형태와 당시 규정에 따라 별도로 필요하다. Vercel Hobby도 개인·비상업 사용 조건을 확인해야 한다.

**트레이드오프**: 배포 전 외부 조건을 점검해야 한다. 법적 판단이 필요한 변경은 별도로 검토한다.
